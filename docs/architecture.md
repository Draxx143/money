# Architecture

The code is organised so that every layer can be tested on its own and so that
no layer reaches into another one's private state.

```
src/
  main.cpp            entry point: arguments, application object, main window
  core/               no Qt Widgets dependency, no user interface
    Logging           ring buffer + rotating log file + Qt message handler
    Paths             XDG locations, overridable with PCB_WORKBENCH_HOME
    ProjectModel      the unified data model and its JSON serialisation
    Project           the .pwb document: open, save, autosave, recovery
    Version.h.in      generated by CMake
  application/        services that are not widgets
    Application       service locator (settings, identity, project)
    AppIdentity       the configurable identity (name, subtitle, colours, icon)
    Settings          the INI configuration store, recent files
  ui/                 Qt Widgets
    MainWindow        menus, toolbar, docks, status bar, workspace persistence
    BoardView         QGraphicsView based board viewer
    ComponentExplorer filterable component list
    AssistantPanel    status of the optional AI features
    LogPanel          log viewer
    SettingsDialog    the nine page settings dialog
    Theme             palette and stylesheet
tests/
  unit/               one binary per subsystem, no Qt Widgets where avoidable
  integration/        document and subsystem interaction
  ui/                 real widgets, driven offscreen
```

## Rules

* **`core` may not use Qt Widgets.** Anything that needs a widget lives in `ui`.
  This keeps the model testable without a GUI.
* **Every value carries provenance and a verification status.** A number in the
  model is never a bare number: it records where it came from (measured,
  extracted from a file copied from the internet, suggested by a model, typed by
  the user) and whether anybody has verified it.
* **Cross references use stable `uid`s**, never row indices and never reference
  designators (which are reused across board revisions).
* **Unknown stays unknown.** Missing data is modelled with explicit
  `has…` flags instead of zero-filled placeholders, so a report can say "not
  measured" instead of "0 V".
* **Every menu action is connected.** A menu entry is only shown when it does
  something; there are no placeholders. A unit test
  (`tests/ui/test_mainwindow.cpp`) walks the menu bar and fails on any action
  without a label.
* **The application name is configuration.** `AppIdentity` is the only source of
  the product name; nothing hardcodes it.

## Build

```
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release -DUSE_SYSTEM_QT6=ON
cmake --build build
ctest --test-dir build --output-on-failure
cmake --build build --target package     # produces the .deb in dist/
```

With `-DUSE_SYSTEM_QT6=OFF` (the default in this repository, because the
development container has no Qt 6 development packages) the script
`scripts/toolchain/setup-toolchain.sh` builds the missing host tools from the
Qt sources and `cmake/Qt6Runtime.cmake` supplies imported targets for the
libraries that ship with the Qt runtime.

## Testing

`ctest` runs three groups: `unit/*`, `integration/*` and `ui/*`. UI tests run
with `QT_QPA_PLATFORM=offscreen`, so they work on a build server without a
display. Every test redirects the whole application state into a temporary
directory (`PCB_WORKBENCH_HOME`), so running the suite has no effect on the
user's configuration.
